# Sentence Break

여러 문장이 한 줄에 붙어 있는 프로즈 텍스트를 받아, **문장 하나를 한 줄**에 두고
**문장 사이에는 빈 줄을 하나**(엔터 두 번) 넣는다. 이 저장소에서는
`authoring-principles.md` "문장은 빈 줄로 끊습니다" 규칙을 기계적으로 적용하는 역할이다.

이 스킬은 **줄바꿈만** 넣는다. 단어·표현·수치는 한 글자도 바꾸지 않는다.

## 대상

- 사용자가 대화에 직접 붙여넣은 텍스트 블록 → 결과를 대화 응답에 그대로 반환한다.
- 사용자가 지정한 파일 → 그 파일을 직접 고친다.
  - 파일이 `content/` 안에 있으면, 고치기 전에
    `python3 polish/tools/snapshot.py create --note "sentence-break: {파일명}"` 로
    스냅샷을 뜨고, 고친 뒤 `python3 polish/tools/guard.py --only {경로}` 로
    보호 구간을 검증한다. 위반이 나오면 `--restore` 로 되돌리고 사용자에게 보고한다.
    (`FINALIZED.md` 에서 잠긴 문서는 훅이 Edit 자체를 막는다 - 잠금 해제 없이는 건드리지 않는다.)
  - `content/` 밖 파일은 스냅샷 없이 바로 고친다.

## 처리 범위 - 순수 프로즈만

문장 분리는 **순수 프로즈 문단**에만 적용한다. 아래는 원래 구조를 그대로 두고 건드리지 않는다.

- 코드 블록(펜스 안), 인라인 코드
- 표의 셀
- 리스트 항목(`-`, `1.` 등) - 항목 하나가 여러 문장이어도 그 항목 안에서는 쪼개지 않는다
- 헤딩 텍스트
- `!!!` 콜아웃(`warning`·`danger`·`info`·`tip`·`note`) 안 문장
- 링크·이미지 경로, 인용구(`>`) 안 출처 표기

이 목록은 `polish/style/checklist.md` 의 보호 구간·제외 목록과 같다. 프로즈 문단
바깥에서 문장을 쪼개면 표·리스트·콜아웃의 구조가 깨진다.

## 문장 경계 판정

문장의 끝은 `.` `!` `?` (뒤에 닫는 따옴표·괄호가 붙을 수 있음) 다음에 공백이나
줄 끝이 오는 지점이다. 아래는 문장 끝이 **아니다** - 쪼개지 않는다.

- 소수점·버전 번호 안의 점 (`3.11.9`, `GPT-4.1`)
- 날짜 안의 점 (`2026.09.07`)
- 줄임표(`...`, `…`)
- 인라인 코드(`` `...` ``)나 링크(`[텍스트](url)`) 안에 있는 문장부호
- 목록 번호 뒤의 점(`1.`, `2.`)

판단이 애매하면(축약어, 인용 안 마침표 등) 원문을 보존하는 쪽으로 결정한다 -
잘못 쪼개는 것보다 안 쪼개는 게 안전하다.

## 하지 않는 것

- 문장 내부에서 줄바꿈 - 한 문장은 아무리 길어도 한 줄에 그대로 둔다.
- 단어·조사·어미·수치·링크 변경 - 순수 공백(개행) 작업이다.
- 이미 문장 단위로 빈 줄이 들어간 문단 재작업 - 이미 규칙을 지킨 문단은 그대로 둔다(멱등).
- 리스트·표·콜아웃·코드블록 구조를 문단으로 착각해 펼치는 것.

## 예시

입력:

```
핵심 전제는 조직들이 1년 전만 해도 상상할 수 없던 속도로 AI를 활용해 코드를 작성하게 됐지만, 코드를 둘러싼 프로세스는 그만큼 빠르게 바뀌지 않았다는 겁니다. 많은 엔지니어링 팀이 여전히 동일한 승인 게이트, 리뷰, 인수인계, 정책을 유지하고 있어서 에이전틱 코딩 도구가 만들어낸 생산성 향상이 정체되고 있다는 거죠.
```

출력:

```
핵심 전제는 조직들이 1년 전만 해도 상상할 수 없던 속도로 AI를 활용해 코드를 작성하게 됐지만, 코드를 둘러싼 프로세스는 그만큼 빠르게 바뀌지 않았다는 겁니다.

많은 엔지니어링 팀이 여전히 동일한 승인 게이트, 리뷰, 인수인계, 정책을 유지하고 있어서 에이전틱 코딩 도구가 만들어낸 생산성 향상이 정체되고 있다는 거죠.
```

## 마무리

- 파일을 고쳤으면 몇 문단·몇 군데에 빈 줄을 넣었는지 요약해 보고한다.
- `content/` 파일이었으면 가드 통과 여부도 함께 보고한다.
- 붙여넣은 텍스트였으면 변환 결과만 응답으로 돌려준다.

# 페이지 유형

책은 처음부터 끝까지 읽지만, 문서 사이트는 검색으로 낱장에 들어옵니다.
그래서 이 사이트에서 좋은 문서는 **변주된 문서가 아니라 예측 가능한 문서**입니다.
같은 유형이면 같은 골격을 씁니다.

검수자는 문서가 어떤 유형인지 먼저 정한 뒤, 그 유형의 필수 요소가 있는지 봅니다.

## 색인 (`index.md`)

- **할 일:** 이 구역에 무엇이 있는지 한눈에 보여 줍니다.
- **리드 문단:** 이 구역이 다루는 범위를 한두 문장으로.
- **필수:** 하위 문서 목록과 각 문서를 한 줄로 설명하는 문장.
- **흔한 실패:** 목록만 있고 설명이 없음 / 본문 내용을 여기서 다 설명해 버림.

## 개념

- **할 일:** 무엇인지, 왜 있는지 이해시킵니다. 따라 할 절차가 목적이 아닙니다.
- **리드 문단:** 한 문장 정의. "~은 …입니다."
- **필수:** 정의 → 왜 필요한가 → 구성 요소나 구분 → 흔한 오해.
- **흔한 실패:** 정의 없이 배경부터 / 개념 문서에 설치 절차가 섞임.

## 하우투

- **할 일:** 따라 하면 됩니다.
- **리드 문단:** 이 문서를 끝내면 무엇이 되는지.
- **필수:** 전제 조건 → 번호 매긴 단계 → 확인 방법 → 실패했을 때.
- **단계는 한 동작씩.** 한 단계에 두 가지를 시키지 않습니다.
- **흔한 실패:** 확인 방법이 없음 / 배경 설명이 절차보다 김.

## 레퍼런스

- **할 일:** 찾아보는 문서입니다. 읽는 문서가 아닙니다.
- **리드 문단:** 무엇의 목록인지, 어떤 기준으로 정렬했는지.
- **필수:** 표 또는 일정한 형식의 반복 항목. 항목마다 같은 필드.
- **흔한 실패:** 항목마다 설명 깊이가 들쭉날쭉 / 서술형으로 늘어짐.

## 사례

- **할 일:** 실제로 어떻게 됐는지 보여 줍니다.
- **리드 문단:** 무엇을, 어떤 상황에서, 결과가 어땠는지.
- **필수:** 상황 → 한 일 → 결과(가능하면 수치) → 배운 것.
- **흔한 실패:** 배운 것이 없음 / 결과가 없이 과정만.

## 어느 유형에도 해당하는 것

- 리드 문단은 **필수**입니다. 검색으로 들어온 독자는 이 문단만 읽고 뒤로 갑니다.
  책에서 금지하는 "이 문서에서는 ~를 다룹니다" 식 선언이 여기서는 오히려 필요합니다.
- H1 은 문서당 하나입니다.
- 첫 화면에서 스크롤 없이 "여기가 어디인지" 가 보여야 합니다.

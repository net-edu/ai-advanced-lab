# 확정 판정 (누적)

검수 중에 내린 판정 가운데 **다음 작업에도 계속 적용되는 것**만 여기 모읍니다.
`style-guardian` 과 `copy-editor` 는 작업을 시작하기 전에 이 파일을 반드시 읽습니다.

왜 파일인가 - 판정을 대화로만 전달하면 다음 파에 도달하지 않습니다. 같은 논쟁을
문서마다 다시 하게 되고, 판정이 문서마다 달라집니다.

## 규범으로 승격하기

이 파일은 계속 자랍니다. 같은 판정이 **세 번 이상** 반복되면 임시 판정이 아니라 규칙입니다.
`voice.md` 나 `checklist.md` 로 옮기고, 여기에는 승격 사실 한 줄만 남깁니다.

```
## 2026-09-01 · (승격) 서사 캡션 예외 → voice.md '어체 예외' 절
```

## 형식

```
## YYYY-MM-DD · 무엇에 대한 판정인가
- 판정: (한 줄)
- 근거: (왜)
- 적용 범위: (전체 / 특정 유형 / 특정 문서)
```

---

## 2026-08-25 · 서사 캡션은 어체 이탈이 아닙니다

- 판정: `▶ *…*` 형태로 흐름을 짚는 캡션은 본문 어체(합니다체)를 따르지 않아도 됩니다.
- 근거: `curriculum/flow.md` 의 평어체 14건이 전부 이 캡션이었습니다. 규칙을 그대로
  적용하면 의도된 장치를 지우게 됩니다. `measure.py` 도 어체 통계에서 제외합니다.
- 적용 범위: 전체.

## 2026-08-25 · 영문 용어의 한글 표기는 아직 강제하지 않습니다

- 판정: `harness`·`context`·`skill`·`hook` 의 한글 표기 권장은 [glossary.md](glossary.md)에
  적어 두되, 검사 표에는 넣지 않습니다.
- 근거: 이 낱말들은 제목·고유명사·코드에서 영문으로 쓰이는 것이 정당합니다.
  한 파를 돌려 오탐 비율을 본 뒤 옮깁니다.
- 적용 범위: 전체. 다음 파에서 재검토.

## 2026-08-27 · 이미 확립된 사실 숫자를 문장에 다시 쓰는 것은 가드 위반이 아닙니다

- 판정: 같은 문서에 이미 여러 번 나온 사실 숫자(예: "3일" 과정 길이)를 문장을 나누며
  다시 적는 것은 새 사실이 아니므로 허용합니다. `guard.py` 의 "산문 숫자 생김" 은 이
  경우 오탐입니다.
- 근거: `course/timetable.md` 5줄 `하루 8교시 = 24교시` 가 `×3일` 생략으로 모순처럼
  읽혀 `하루 8교시입니다.` + `3일이면 24교시입니다.` 로 나눴습니다. "3일" 은 같은 문서
  3·9줄에 이미 있는 과정 길이입니다. 사용자가 이 문안을 승인했습니다.
- 적용 범위: 전체. 단, 값이 바뀌거나 처음 등장하는 수치는 여전히 보호합니다.

## 2026-08-31 · 하우투 문서의 `-세요` 지시문이 만든 혼재율 초과는 어체 이탈이 아닙니다

- 판정: 실습·하우투 문서에서 `measure.py` 의 어체 혼재율이 임계값(25%)을 넘어도, 그
  혼재의 정체가 합니다체 서술문 대 독자 지시문(`-하세요`·`-확인하세요`)의 분할이면
  어체 이탈이 아닙니다. `voice.md` 는 지시문에 `-세요` 를 쓰라고 하므로 정상 표현이며,
  임계값 초과는 지시문이 잦은 하우투 문서의 구조적 오탐입니다.
- 근거: `content/warmup/` 5개 문서에서 일관되게 확인했습니다. 예로 `markdown.md` 는
  혼재 29%(합니다체 5·명령형 2), 리드를 두 문장으로 끊자 38%로 올랐지만 평어체는
  0건이었습니다. 다른 네 문서도 같은 구조였습니다.
- 적용 범위: 하우투·실습 유형. 단, 평어체(`-이다`·`-한다`)가 섞이면 그것은 여전히
  이탈입니다 - 혼재율이 아니라 평어체 유무로 판단합니다. (같은 판정 반복 시 `voice.md`
  '어체 예외' 절로 승격 검토.)

## 2026-09-02 · "지금은 건너뛰어도 됩니다" 콜아웃 반복은 남발이 아닙니다

- 판정: `!!! note "지금은 건너뛰어도 됩니다"` 형태로 초심자가 건너뛸 수 있는 절을
  표시하는 콜아웃은, 한 문서에 여러 번 나와 밀도 임계값(300어절당 1개)을 넘어도 지적하지
  않습니다.
- 근거: `skill-creation.md`, `permissions-and-commands.md`, `mcp/connecting.md` 세 문서의
  style-guardian 검수에서 모두 같은 패턴("심화" 스킵 표시)을 발견하고 지적 대신 질문으로
  남겼습니다. 세 번 반복되어 임시 판정을 규범으로 승격합니다. 서사 캡션 예외와 같은
  이유로, 콜아웃의 기능이 강조가 아니라 "이 절은 지금 몰라도 된다"는 일관된 안내
  장치이기 때문입니다.
- 적용 범위: 전체. `checklist.md` '콜아웃 남발' 행의 예외로 반영 검토 대상.

## 2026-09-01 · 개선 모드에서 사전 승인된 새 링크·인라인 코드는 가드 위반이 아닙니다

- 판정: 개선(revise) 모드에서 사용자가 정확한 문구를 사전에 검토·승인했다면, 그 문구에
  포함된 새 링크·인라인 코드에 대한 `guard.py`의 "링크·미디어 경로 생김"·"인라인 코드
  생김" 위반은 되돌리지 않습니다. 단 숫자는 이 예외에서 제외합니다 - 사실 확인이 필요한
  대상이라 여전히 보호합니다.
- 근거: `guard.py`의 보호 구간은 스타일 편집 중 기존 링크·코드를 실수로 바꾸는 것을
  막기 위한 장치이지, 개선 모드에서 새 내용에 새 링크·명령을 추가하는 것 자체를 막으려는
  게 아닙니다. 헤딩은 개선 모드에서 새로 생겨도 이미 허용하는데(`mode != "revise"` 조건)
  링크·인라인 코드·숫자에는 이 예외가 없어 오탐이 납니다. `what-is-context.md`에
  `/context`·`token-saving.md` 링크 추가, `turn-concept.md`에 시뮬레이터 링크 추가
  사례에서 반복 확인했습니다.
- 적용 범위: 개선 모드 전체. 3회째 반복되면 `guard.py`의 헤딩 예외 조건에 링크·인라인
  코드도 포함시키는 코드 수정으로 승격 검토.

## 2026-09-03 · 헤딩에 이미 있는 번호를 본문 주어로 옮겨 적는 것은 가드 위반이 아닙니다

- 판정: 주어 생략을 보정하며 헤딩(`### 1층 - 맥락공학` 등)에 이미 나온 번호를
  본문 문장의 주어(`1층은 …`)로 옮겨 적는 것은 새 숫자 사실이 아니므로 허용합니다.
  `guard.py`의 "숫자 생김"은 이 경우 오탐입니다.
- 근거: `course/index.md`에서 17·27·38줄의 주어 생략(1층/2층/3층 도입문)을 고치며
  헤딩에 이미 있던 층 번호를 주어로 썼습니다. 2026-08-27 판정(이미 확립된 사실
  숫자의 문장 내 재기술은 위반 아님)과 같은 취지이나, 그 판정은 프로즈 문장 사이
  재기술이고 이번은 헤딩→본문 이동이라 사례를 구분해 남깁니다.
- 적용 범위: 전체. 단, 헤딩에 없던 새 번호이거나 값이 바뀐 경우는 여전히 보호합니다.

## 2026-09-04 · 산정(도메인)과 판정(산출물)은 구분해 공존합니다

- 판정: 기업가치 실습 문서에서 "기업가치 산정"은 실습의 소재·도메인 명칭으로,
  그 산출물은 "판정"(저평가/적정/고평가)으로 부릅니다. 리드가 예시를 '산정'으로
  불러도, 산출물이 '판정'임을 함께 밝히면 어휘 불일치로 지적하지 않습니다.
- 근거: `problem-definition.md` 의 논지는 "적정가 $X 산정(점추정)이 아니라 판정"입니다.
  style-guardian 이 리드의 '산정'을 논지와 충돌한다고 지적했으나, 사용자가 '산정'을
  도메인 명칭으로 유지하기로 결정했습니다. 리드에 산출물이 판정임을 밝히는 문장을
  더해 오해를 없앴습니다(규범과 사용자 지시 충돌 → 사용자 지시를 따름).
- 적용 범위: 기업가치 실습 계열. 단 "적정가 $X 점추정"을 목적·산출물로 삼는 것은
  여전히 논지 위반입니다.

## 2026-09-04 · '클라이맥스'는 stage 서사 문서에서 존치합니다

- 판정: `korean-naturalness.md` §5는 '클라이맥스' 같은 서사 구어를 회피 대상으로 봅니다.
  그러나 stage 계열 문서(`stage5-oracle.md`·`index.md` 등)는 stage5를 '클라이맥스'로 부르는
  일관된 서사 용어로 씁니다. 이 서사 캡션 성격의 쓰임은 지적하지 않습니다.
- 근거: `problem-definition.md` 윤문에서 '클라이맥스' 2회를 '가장 중요한 대목'으로 바꿀 때,
  사용자가 "이 문서만 바꿈"을 선택했습니다. 교안 전체의 서사 용어를 한 문서만 바꾸면 표현이
  어긋나므로, stage 문서의 '클라이맥스'는 의도된 목소리로 남깁니다.
- 적용 범위: stage 계열·서사 흐름 문서. 일반 설명 문단에서 새로 '클라이맥스'를 쓰는 것은
  여전히 §5 대상입니다.

## 2026-09-07 · 문서 안에 이미 있는 인라인 코드·헤딩 번호를 다른 문장에 다시 쓰는 것은 가드 위반이 아닙니다

- 판정: 같은 문서 다른 곳에 이미 나온 인라인 코드(예: `raw`·`sources`·`research`·`curriculum`)를
  별도 문장에 다시 나열하거나, 실제 헤딩 번호(`## 1. …`·`## 2. …`)를 리드 문단에서 `§1`·`§2`
  형태로 참조하는 것은 새 사실이 아니므로 `guard.py`의 "인라인 코드 생김"·"숫자 생김" 오탐입니다.
- 근거: `asset-and-publish.md` 11행에 이미 있는 `raw`→`sources`→`research`→`curriculum` 표기를
  58행에서 비유를 보완하려 다시 씀. `token-saving.md` 리드에 추가한 "(§1)·(§2)·(§3)"가 실제
  `## 1.`·`## 2.`·`## 3.` 헤딩과 정확히 일치함. 둘 다 2026-08-27(숫자 재기술)·2026-09-03
  (헤딩 번호→본문 이동) 판정과 같은 취지이나 대상이 인라인 코드·리드 문단 참조로 넓어져
  별도 사례로 남김.
- 적용 범위: 전체. 단, 문서 안에 없던 새 코드·번호이거나 값이 바뀐 경우는 여전히 보호합니다.

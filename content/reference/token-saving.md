# 토큰 절약 기법

토큰 절약은 "좋은 도구를 하나 깔면 되는 일" 이 아닙니다.

**측정 → 습관 교정 → 구조 개선** 순서를 통해 지속적으로 자신의 사용 패턴을 메타인지해야 합니다.

대부분의 토큰 절감은 도구 사용이 아니라 사용 습관에서 나옵니다.

이 문서는 Anthropic 공식 절감 방법(§1)·워크플로 패턴(§2)·외부 도구와 과장된 주장(§3) 순서로 정리합니다.

## 1. 토큰 사용량을 측정한다

Context window 에 무엇이 올라와 있는지 모르면 최적화가 의미 없습니다.

| 도구 | 보여주는 것 |
|---|---|
| `/context` | 카테고리별 실시간 분해(시스템 프롬프트 · MCP 툴 · 메시지 · 여유 공간) + 로드된 메모리 파일 |
| `/usage` | 세션 토큰 통계. 스킬 · 서브에이전트 · 플러그인 · MCP 서버별 사용량, `d` / `w` 로 24시간 · 7일 전환 |
| statusline | 컨텍스트 사용량 상시 표시 (공식 지원) |
| `ccusage` (커뮤니티) | 로컬 사용 로그를 읽어 일 / 주 / 세션별 분해를 오프라인으로 |

!!! tip "커뮤니티 공통 기준"
    새 세션을 열자마자 `/context` 를 실행시켜보고, **시작부터 context window 의 20% 이상** 이 채워져 있으면

    기본 harness 설정에 문제가 있는 것입니다.

## 2. Anthropic 공식 토큰 절감 방법

### 2-1. 컨텍스트 관리

| 방법 | 내용 |
|---|---|
| `/clear` | 무관한 작업으로 넘어갈 때 초기화. 오래된 컨텍스트는 이후 모든 메시지에서 토큰을 낭비 |
| `/compact [지시문]` | `/compact Focus on code samples and API usage` 처럼 무엇을 보존할지 지정 |
| CLAUDE.md 의 `# Compact instructions` | 압축 동작을 프로젝트 단위로 고정 |
| autocompact | 컨텍스트가 임계치에 가까워지면 자동으로 실행됨 `/compact` 와 달리 지시문을 줄 수 없어 무엇을 보존할지 통제 불가. |


??? details "압축 후 무엇이 살아남나"
    - 프로젝트 루트 CLAUDE.md 와 auto memory 는 디스크에서 **재주입**됩니다.
    - `paths:` frontmatter 가 붙은 rule 과 하위 디렉터리의 중첩 CLAUDE.md 는 해당 파일을
      다시 읽을 때까지 **사라집니다.**
    - 호출된 스킬 본문은 재주입되지만 스킬당 5,000 토큰 · 전체 25,000 토큰 상한이 있고
      오래된 것부터 버려집니다. 잘림은 **앞부분을 남기므로** SKILL.md 는 중요한 지시를
      위쪽에 배치하세요.

### 2-2. 모델 · 사고량 조절

- 대부분의 코딩 작업은 중간 등급 모델로 충분합니다.

- 최상위 모델은 복잡한 아키텍처 결정이나 다단계 추론에만 씁니다.

- 단순한 서브에이전트는 설정에서 더 작은 모델로 지정합니다.

- **Extended thinking** 토큰은 output 으로 과금되고 기본 예산이 요청당 수만 토큰까지 갈 수 있습니다. `/effort` 로 낮추거나 `/config` 에서 끕니다.

- **Advisor 전략** : 저렴한 executor + 강한 advisor 조합.


### 2-3. MCP 오버헤드

- MCP 툴은 기본적으로 on-demand 로 동작합니다.

- Context 에는 MCP tool 이름만 들어가고, 실제로 쓸 때 스키마가 로드됩니다.

- `gh` · `aws` · `gcloud` 같은 CLI 도구는 목록 자체를 추가하지 않기 때문에 MCP 서버보다 **컨텍스트 효율**이 좋습니다.

- `/mcp` 로 안 쓰는 서버는 비활성화하세요.

### 2-4. CLAUDE.md 다이어트 → 스킬로 이전

CLAUDE.md 는 세션 시작 시 로드되므로, PR 리뷰나 DB 마이그레이션 같은 **특정 워크플로 지시**가
들어 있으면 무관한 작업 중에도 그 토큰을 계속 지불합니다.

| CLAUDE.md 크기 | 진단 |
|---|---|
| 300~600 토큰 | 잘 짜인 상태 |
| 2,000 토큰 초과 | 있으면 안 되는 태스크 상태 · 문서를 저장하고 있을 가능성 |
| 5,000 토큰 이상 | 유효 작업 컨텍스트를 유의미하게 깎아먹음 |

스킬이 효율적인 이유는 **progressive disclosure(필요할 때 하나씩 가져와서 쓰는 방식)** 방식으로 작동하기 때문입니다.

부작용이 있는 스킬(커밋 · 배포 · 메시지 전송)에는 `disable-model-invocation: true` 를 걸면 스킬 인덱스에도 올라가지 않아 직접 호출 전까지 **컨텍스트 0**입니다.

### 2-5. Hook 으로 전처리 - 가장 저평가된 레버

Claude 가 10,000줄짜리 로그를 읽어 에러를 찾는 대신, hook 이 `ERROR` 만 grep 해서 돌려주면 컨텍스트가 **수만 토큰에서 수백 토큰으로** 줄어듭니다.

### 2-6. 서브에이전트로 위임

테스트 실행 · 문서 조회 · 로그 처리를 위임하면 장황한 출력은 서브에이전트 컨텍스트에 남고
**요약만** 메인 대화로 돌아옵니다.

공식 시뮬레이션 예시: 6,100 토큰의 파일을 읽었지만
메인에는 420 토큰만 반환됩니다.

!!! warning "반대로 Agent Teams 는 비쌉니다"
    teammate 가 plan 모드로 돌면 표준 세션 대비 약 **7배** 토큰을 씁니다. 각자 자기 컨텍스트
    윈도우를 유지하는 별개 인스턴스이기 때문입니다. 팀은 작게, 태스크는 self-contained 하게,
    끝난 teammate 는 종료하세요.

### 2-7. 프롬프트 캐시를 깨지 않기

캐시는 요청의 **앞부분(prefix)을 정확히 매칭**하므로, prefix 안의 어떤 변경도 그 이후 전부를
재계산시킵니다.

캐시를 깨는 대표 행동:

- `/model` 로 모델 전환 - 모델마다 별도 캐시. effort level 도 캐시 키의 일부이며,
  MCP 툴 세트 변경도 시스템 프롬프트 레이어라 무효화됩니다
- 캐시 수명보다 긴 휴식 후 첫 메시지 - 전체 컨텍스트 재처리
- `/compact` 자체가 요약할 대화를 읽으므로 큰 컨텍스트 압축은 그 자체로 큰 요청입니다.
  연속성이 필요 없다면 **`/clear` 는 공짜**입니다

## 3. 워크플로 패턴 - 도구보다 효과가 크다

### Document & Clear (dev-docs 3파일 시스템)

커뮤니티에서 가장 널리 수렴된 패턴입니다. 태스크 상태를 **대화 밖 파일**에 둡니다.

| 파일 | 담는 것 |
|---|---|
| `plan.md` | 승인된 전략 |
| `context.md` | 현재 상태와 핵심 결정 |
| `tasks.md` | 진행 체크리스트 |

압축 전에 상태를 저장하고, 압축 후 "continue" 라고 하면 Claude 가 파일을 읽어 재설명 없이
이어갑니다.

### 그 밖의 패턴

- **작업 단위로 세션 분리** : 완전히 다른 영역으로 넘어갈 때, 히스토리 토큰이 전체의 50% 를
  넘을 때가 분리 시점입니다.
- **미리 압축** : 자동 압축도 토큰을 소비합니다. 95% 까지 쌓고 요약하는 것보다 50% 에서
  미리 압축하는 편이 쌉니다.
- **context rot 인식** : 대략 300,000~400,000 토큰을 넘으면 어텐션이 넓게 분산돼 응답 품질이
  떨어집니다. 컨텍스트가 꽉 찬 게 아니라 **오염된** 상태입니다. 큰 컨텍스트 윈도우는 목표가
  아니라 비상용 보험입니다. [(Context Engineering 참고)](../concepts/context-engineering.md#참고-input-token-증가에-따른-context-rot)

## 4. 외부 도구와 과장된 주장 ⚠️

**커뮤니티 에서 회자되는 토큰 절감 툴들의 벤치마크는 마케팅에 가깝습니다.**

이 절이 이 문서에서 가장 실용적입니다.

| 도구 | tool 홍보를 위한 절감률 | 통제 실험 결과 |
|---|---|---|
| 출력 압축 스킬(caveman 류) | 65~75% | 장기 에이전틱 코딩 실행 기준 **8.5%**. output 토큰만 줄이고 input · reasoning 은 손대지 않으며, 스킬 자체가 턴당 1~1.5k input 토큰을 추가 |
| 셸 출력 필터(rtk 류) | 60~90% | low effort 에서 **7.6% 더 비쌌고**(p=0.004), high effort 에서 ±0%. 태스크 품질은 양쪽 변화 없음 |

### 실전 순서

1. `/context` + `/usage` 로 **베이스라인 측정**
2. Anthropic 공식 권장 습관 (CLAUDE.md 다이어트 · `/clear` 규율 · 서브에이전트 위임 · 모델/effort 매칭 · hook 전처리)
3. 캐시 무효화 습관 교정 (모델 스위칭 자제, MCP 세트 고정)
